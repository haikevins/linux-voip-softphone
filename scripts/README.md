# Script Taxonomy

The `scripts/` tree contains executable repository workflows. Directories define responsibility so filenames do not need to repeat repository-wide or phase context.

## Layout

```text

├── setup/
│   └── bootstrap.sh
├── dev/
│   ├── build.sh
│   └── test.sh
├── quality/

│   ├── verify-docs-structure.sh
│   └── verify-evidence-structure.sh
├── phase0/

├── phase1/
│   ├── verify.sh
│   └── collect-evidence.sh
├── phase2/
```

## Responsibilities

- `setup/` installs or prepares developer prerequisites.
- `dev/` provides routine local build and test entry points.
- `quality/` contains reusable repository-wide quality and structure gates.
- `phaseN/` contains phase-specific verification, integration, and evidence collection workflows.

## Conventions

- Shell entry points use Bash and `set -euo pipefail`.
- Scripts that operate on repository files resolve the repository root relative to their own location and do not depend on the caller's working directory.
- Verification scripts do not generate committed evidence unless an explicit phase-specific capture mode documents that behavior.
- Evidence collectors write only to their matching `evidence/phaseN/` namespace.
- Maintained README policy documents are never generated by evidence collectors.
- SIP credentials, Digest Authorization material, SRTP inline key material, and raw packet captures must not be written to committed evidence.
- Shared shell libraries are introduced only when repeated implementation justifies them; no `lib/` layer exists merely for symmetry.

## Common entry points

```bash
./scripts/dev/build.sh
./scripts/dev/test.sh
./scripts/quality/sanitizers.sh
./scripts/quality/clang-tidy.sh
./scripts/quality/verify-docs-structure.sh
./scripts/quality/verify-evidence-structure.sh
./scripts/phase5/verify.sh
./scripts/phase6/verify.sh
./scripts/phase7/verify.sh
```

`phase6/verify.sh` first checks the audio environment, then reuses the Phase 5
quality and regression gate and explicitly runs the RTP statistics and PJSUA2
RTP diagnostics suites. It validates only automated checks; outgoing/incoming
calls, audible two-way audio, and live RTP results remain manual gates.

`phase7/verify.sh` reuses the Phase 6 gate, builds the Qt-only and Qt+PJSIP
configurations, runs the Phase 7-labeled controller/ViewModel tests, executes
the offscreen GUI launch smoke test, and validates documentation/evidence
structure. Live SIP registration/calls and audible two-way audio remain manual
evidence even after the automated script passes.

Phase-specific documentation under `docs/phaseN/` remains the authoritative source for each phase workflow and prerequisites.
