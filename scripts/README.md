# Script Taxonomy

The `scripts/` tree contains executable repository workflows. Directories define responsibility so filenames do not need to repeat repository-wide or phase context.

## Layout

```text
scripts/
├── setup/
│   └── bootstrap.sh
├── dev/
│   ├── build.sh
│   └── test.sh
├── quality/
│   ├── clang-tidy.sh
│   ├── sanitizers.sh
│   ├── verify-docs-structure.sh
│   └── verify-evidence-structure.sh
├── phase0/ ... phase6/
│   └── historical phase-specific verification/evidence workflows
└── phase8/
    ├── verify.sh
    ├── verify-final-runtime-acceptance.sh
    ├── verify-roadmap-exit.sh
    ├── verify-pjsip-live-lifecycle-evidence.sh
    ├── run-pjsip-live-lifecycle-probe.sh
    ├── verify-queue.sh
    ├── verify-stress.sh
    ├── verify-tsan.sh
    ├── verify-qt-ownership.sh
    ├── verify-pjsip-*.sh
    ├── verify-ci-clang-*.sh
    ├── audit-*.py
    └── gui-runtime-probe.py
```

There is no `scripts/phase7/` directory. Phase 7 reused the repository-wide quality gates, Qt/PJSIP CMake/CTest presets, and the inherited Phase 6 regression gate rather than introducing a redundant phase wrapper.

## Responsibilities

- `setup/` installs or prepares developer prerequisites.
- `dev/` provides routine local build and test entry points.
- `quality/` contains reusable repository-wide quality and structure gates.
- `phaseN/` contains phase-specific verification, integration, and evidence collection workflows.
- `phase8/verify.sh` is the Phase 8 aggregate automated **offline** gate. It validates documentation/evidence structure, script syntax, the recorded live-evidence summary, the final offline runtime acceptance workflow, and the roadmap/source audit. It does not execute live SIP or authorize PJSUA2 shutdown safety.
- `phase8/run-pjsip-live-lifecycle-probe.sh` is an explicit opt-in real-SIP experiment (`PHASE8_LIVE_SIP=1`). It is deliberately excluded from the offline aggregate and may briefly ring the configured target extension. Normal runs require a clean checkout; `PHASE8_ALLOW_DIRTY=1` is reserved for guarded pre-commit validation and requires the working-tree state to be unchanged by the probe.

## Conventions

- Shell entry points use Bash and `set -euo pipefail`.
- Scripts that operate on repository files resolve the repository root relative to their own location and do not depend on the caller's working directory.
- Verification scripts do not generate committed evidence unless an explicit phase-specific capture mode documents that behavior.
- Evidence collectors write only to their matching `evidence/phaseN/` namespace.
- Maintained README policy documents are never generated by evidence collectors.
- SIP credentials, Digest Authorization material, SRTP inline key material, and raw packet captures must not be written to committed evidence.
- Shared shell libraries are introduced only when repeated implementation justifies them; no `lib/` layer exists merely for symmetry.
- A PASS from an offline/synthetic gate must not be described as proof of live SIP/PJSUA2 callback quiescence, shutdown safety, leak freedom, or media behavior unless that property was actually exercised.

## Common entry points

```bash
./scripts/dev/build.sh
./scripts/dev/test.sh
./scripts/quality/sanitizers.sh
./scripts/quality/clang-tidy.sh
./scripts/quality/verify-docs-structure.sh
./scripts/quality/verify-evidence-structure.sh
./scripts/phase5/verify.sh
./scripts/phase6/verify.sh
./scripts/phase8/verify.sh
```

`phase6/verify.sh` first checks the audio environment, then reuses the Phase 5 quality and regression gate and explicitly runs the RTP statistics and PJSUA2 RTP diagnostics suites. It validates only automated checks; outgoing/incoming calls, audible two-way audio, and live RTP results remain manual gates.

`phase8/verify.sh` intentionally remains an offline aggregate. It validates the committed sanitized live-lifecycle summary but never replays the real SIP experiment. It delegates to the reviewed Phase 8 acceptance and roadmap gates, preserves the `BLOCKED/UNPROVEN` external-quiescence boundary, and leaves graphical/manual GUI acceptance to the explicit `verify-final-runtime-acceptance.sh --manual` invocation.

Phase-specific documentation under `docs/phaseN/` remains the authoritative source for each phase workflow and prerequisites.
